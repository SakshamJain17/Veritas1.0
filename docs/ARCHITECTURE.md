# Architecture

The Next.js workspace calls FastAPI for uploads, claim lists, synthetic registry checks, TinyFish investigations, reviews, comparisons, and attestations. SQLAlchemy stores documents, claims, evidence, runs, reviews, comparisons, audit events, source registrations, and attestations in SQLite by default or PostgreSQL through `DATABASE_URL`. Uploads are stored on the API host's private filesystem. A deployed installation needs durable storage for the database and originals.

PDF embedded text is extracted by PyMuPDF. Tesseract handles scanned PDFs and images, returning OCR words and normalized source boxes. Deterministic patterns extract the supported atomic fields. Every claim starts at `pending_review`. Neither OCR confidence nor presence in a document proves the claim.

The local synthetic registry exposes fictional JSON records. The API retrieves them over HTTP, checks record and field scope, normalizes values, stores the response digest, and produces supported, contradicted or unverified decisions. The independent TinyFish path uses Search for discovery, Fetch for public pages, Browser for CDP-driven form lookup, and Agent for a bounded async goal. A Search snippet never creates claim evidence.

Register exact public hostnames with reviewer-only `POST /sources` or configure `VERITAS_APPROVED_HOSTS` before remote Fetch, Browser, or Agent runs. The API validates both requested Fetch URLs and final URLs. Localhost is used only for the separately configured local synthetic registry check. To support a claim, retrieved observations must come from a registered issuer authorized for that field, contain the observed value, normalize to a comparable value, and match record and jurisdiction scope. Eligible observations update claim status; contradictory eligible observations are preserved as `conflicting`. Search candidates never update claim status.

The investigation-plan endpoint chooses Search, Fetch, Browser or Agent based on whether the source is registered and whether the task needs interaction or multiple pages. Search/Fetch, Browser and Agent remain separate executable capabilities. Browser records actual steps and a screenshot, blocks cross-host top-level navigation, and closes its managed session. Agent returns an asynchronous run ID and is polled to a persisted terminal state. Agent goals are constrained in text to the source host, while evidence acceptance enforces the final source allowlist; the provider does not expose a per-navigation domain enforcement hook here.

Reviewers can correct normalized extraction values, approve/reject extraction, and approve/reject evidence. A correction invalidates prior evidence value checks until re-evaluation. Extraction approval cannot resolve an existing evidence conflict. Evidence approval requires source, span and scope checks plus a comparable value. Public attestations are snapshots with selected evidence references, not live claim-status queries. Revocation is separately checked on every public lookup.

Canonical JSON SHA-256 attestation hashes are separate from uploaded document SHA-256 fingerprints. The QR endpoint encodes the public verification URL. No blockchain transaction is implied.

PostgreSQL is supported through SQLAlchemy, but formal schema migrations, issuer signing, distributed job execution, production hardening, and live TinyFish account verification remain deployment work. No TinyFish capability is claimed verified without a configured account and live test.

The frontend uses Next.js 16, typed React components, locally served Geist fonts and Motion. CSS is split into tokens/base controls, landing composition, workspace layout, and responsive refinements. Heavier workspace sections load on demand. Document pages are rendered by the API and source boxes use normalized coordinates so zoom preserves alignment. Long-running work uses FastAPI background tasks; queued jobs are not a durable distributed worker system.
